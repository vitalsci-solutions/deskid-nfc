Metratec DeskID NFC, in the browser

Tag presence events and NDEF read and write over WebSerial, with the reader's four firmware quirks already handled.

Get started GitHub
npm i deskid-nfc 
import { DeskIdNfc } from 'deskid-nfc';

const nfc = new DeskIdNfc();

nfc.on('tag', async (tag) => {
  const { records } = await nfc.read(tag.uid);
  console.log(tag.uid, records);
});

// WebSerial needs a user gesture
button.onclick = () => nfc.open();

Four firmware behaviours, already handled

The reader speaks an AT-style line protocol over USB CDC, and it works right up until it doesn't. These four behaviours cause almost every confusing failure. Each one is handled inside the package, on firmware 2.08.

+INV: <NO TAGS FOUND>

The RF field idles off

A cold inventory round misses a tag that is sitting on the antenna. The field is switched on at connect and stays energized for the whole session.

+SEL: <Tag timeout>

Tags park in HALT state

After a completed read the tag is halted, and this firmware cannot address a halted tag, so every second read fails. The field is power-cycled and the select retried.

+CINV: events you never started

Scans outlive the port

Continuous inventory keeps running inside the reader after the port closes, and its rounds collide with reads. Stale scans are cleared at connect, and stopped at close.

~50 lines per second

Idle rounds flood the link

Empty inventory rounds drown a log pipeline and starve the UI. Round markers are filtered in the transport, so only real tag sightings reach your code.

The whole API in one screen

Continuous inventory runs while the port is open, so tag presence is an event, not a poll. Read and write pause that loop and resume it for you, and queue behind each other. 

import { DeskIdNfc, isTagRemovedError, ndefRecordToString } from 'deskid-nfc';

const nfc = new DeskIdNfc();

nfc.on('tag', (tag) => show(tag.uid));            // a tag landed on the reader
nfc.on('tagleft', () => show(null));              // it was taken away
nfc.on('log', (entry) => trace(entry.text));      // every TX and RX line
nfc.on('close', (reason) => show(null));          // 'requested' or 'lost'

const info = await nfc.open();                    // picker, probe, init, watch
info.firmware;                                    // 'DeskID_NFC 0208'

const { state, records } = await nfc.read();      // 'RW', decoded NDEF records
records.map(ndefRecordToString);                  // ['moin']

try {
  await nfc.write({ kind: 'uri', uri: 'https://example.com' });
} catch (error) {
  // the one failure worth its own UX: the tag was moved away
  if (!isTagRemovedError(error)) throw error;
}

await nfc.close();                                // stop scanning, field off, port released

What it was tested against

Reader
Metratec DeskID NFC, firmware 2.08, hardware 0103, over USB CDC-ACM with no driver
Tags
NTAG213 (ISO14443A, NFC Forum Type 2), read, write, format and NDEF state checks
Browsers
Chromium 89 and newer (Chrome, Edge, Arc, Brave) on HTTPS or localhost. Firefox and Safari do not implement WebSerial
Not tested
ISO15693 vicinity tags, and several tags on the antenna at once
